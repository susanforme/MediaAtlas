# ADR-004：SQLite、Repository 与安全数据生命周期

- 状态：架构采用；P1 设计并实施迁移。
- 日期：2026-11-03。
- 当前相关文档：[架构与 IPC](../architecture.md)、[自动媒体库](../automatic-library.md)。

## 背景

应用本地优先，首版单机使用，需要分页媒体查询、字段来源、持久化任务以及中断恢复。数据库应与 UI 和领域规则隔离。

## 决策

- 使用 SQLite + SQLx migrations。开启外键、WAL 和 busy_timeout，SQL 由 Repository 封装；UI 和业务模块不直接拼 SQL。
- 采用稳定主键和 UTC 时间。实体使用 UUID v4；未实现业务不预建空表。
- 公共表与类型扩展表分离；外部 ID、来源、文件、图片、人员和关系独立保存。P1 先实现必要 Repository，其他表按对应业务阶段追加。
- 为媒体类型/更新时间、外部 ID、Root/相对路径和常用查询建立索引；分页优先 cursor/keyset，避免大量 offset 扫描。
- 已发布 migration 只能追加，禁止改写。Schema 设计和约束先审查，再实施迁移、唯一性、外键及跨平台路径测试。
- 任务和执行记录持久化；重启将运行中任务标记为 Interrupted，不自动重放移动或覆盖文件的任务。文件操作保存计划、执行步骤和恢复信息。
- “从媒体库移除”与“删除磁盘文件”是不同能力，默认只移除索引。数据库删除不应隐式删除媒体源文件。
- 备份使用 SQLite backup API 或一致性安全快照，不直接复制正在写入的数据库。恢复功能和升级数据保留在 P8 验收。
- 数据库、缓存位于本机应用数据目录；API Key/Cookie 等敏感配置按专门凭据边界管理，不能因存在 settings 表就明文写入或输出日志。

## 影响

模型和 Schema 变化先明确约束，再通过追加迁移实施；本地索引用于幂等与增量扫描，不伪造成功迁移记录。单机 SQLite 满足首版目标；云端账号和同步不在当前范围。
