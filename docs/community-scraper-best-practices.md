# 社区刮削工具实践与 MediaAtlas 后续优化

调研日期：2026-11-03。代码对照基线：`708fcdbe18eb4ca33984923ec1d9fd4624621af2`。

> 后续用户已明确将默认工作流调整为 Emby 式“添加目录 → 后台扫描/索引/自动刮削 → 直接浏览”，成人资源统一为前端资源类型。本文保留当时调研基线；其中逐项确认作为默认路径、可信元数据作为媒体可见前提的建议已被替代，最新行为见 [自动媒体库与首屏加载](automatic-library.md)。手动队列用于异常处理，文件输出仍需确认。

本文是后续开发依据，区分社区证据、当前实现和待实施建议。优先解决“选目录、找资源、核对匹配、遇错继续”这条主线。以下优先级是本项目的产品判断，不代表社区项目的统一标准；建议不等于已实现或已验收。

## 1. 查阅来源与可借鉴实践

采用项目自身文档和公开代码作为依据。链接固定到查阅版本；没有运行这些第三方桌面应用，也没有据此宣称其所有平台体验已验证。tinyMediaManager 的公开源码和具体发行版功能、授权范围应分别核对；本次只参考工作流，不引入第三方代码或依赖。

| 编号 | 一手来源 | 核对到的实践 | 对 MediaAtlas 的意义 |
| --- | --- | --- | --- |
| S1 | [MediaElch 快速入门](https://github.com/mediaelch/mediaelch-doc/blob/4f5a3efce5ad2d52595bd16945fbee5999a53569/docs/source/quick-start.rst) | 添加并选择媒体目录、指定类型、重新加载；解释电影独立目录和剧集季目录的识别方式 | 目录选择应是主入口；目录结构问题应在扫描反馈中体现，不能要求用户先理解内部配置 |
| S2 | [MediaElch 电影工作流](https://github.com/mediaelch/mediaelch-doc/blob/4f5a3efce5ad2d52595bd16945fbee5999a53569/docs/source/movie/index.rst) | 选择一部或多部电影、选择抓取字段、手动选择正确候选、过滤和键盘操作；不同图片来源可能使用不同语言设置 | 批量选择与逐项确认可同时存在；字段和图片语言要清楚；快捷键需要可发现 |

| S4 | [tinyMediaManager 缺失字段筛选](https://gitlab.com/tinyMediaManager/tinyMediaManager/-/blob/e813864038d8f2bbed1428a714b81e3b317f5ac1/src/main/java/org/tinymediamanager/ui/movies/filters/MovieMissingMetadataFilter.java) | 选择具体元数据字段，检测哪些影片缺失这些字段 | “资料不足”之外，可增加明确的缺失字段筛选，不靠当前页前端猜测 |
| S5 | [tinyMediaManager 电影刮削任务](https://gitlab.com/tinyMediaManager/tinyMediaManager/-/blob/e813864038d8f2bbed1428a714b81e3b317f5ac1/src/main/java/org/tinymediamanager/core/movie/tasks/MovieScrapeTask.java) | 逐项选择对话框、当前项与总数、返回上一项、停止队列、覆盖策略参数 | 明确展示处理位置和退出方式；覆盖选择必须服从本项目的字段保护和输出权限 |

S6 尤其说明：自动化不必等于自动接受。beets 提供逐项确认模式及弱匹配暂缓策略。MediaAtlas 可减少重复输入、自动准备候选，但继续由用户明确确认匹配和实际写入。S1 的推荐目录结构只作为诊断参考，不强制用户重命名或搬动已有文件。

## 3. 优先优化清单

P0：优先降低流程中断和重复操作。P1：提高批量处理准确性与效率。P2：前两级稳定后再扩展。每项都应单独交付、验证和提交。

### P0-1：统一资源选择入口，返回原清单

- 问题：从工具清单进入已有分页和批选，直接进入刮削页却回到有限下拉选择；完成后找不回刚才的筛选位置。
- 方案：直接进入刮削页时使用共享资源选择器或明确进入工具清单选择。复用后端过滤、分页和选择模型；保留受校验的返回上下文，不接受任意返回 URL。无本地资源时引导添加目录或处理扫描候选。
- 验收：超过 48 项的库能找到末页目标；返回后恢复有效筛选、排序和位置；游标过期则回到第一页并解释；普通入口始终排除成人资源。
- 依据：S2、S3；涉及 tools、scraper 和薄路由，共享选择模型由单人负责。

### P0-2：把首次导入串成可继续的流程

- 问题：原生选目录已解决手填路径，但新用户仍需要理解目录、扫描候选、工具索引和可信媒体库之间的关系。
- 方案：在实际完成状态上串联“选目录 → 保存并扫描 → 核对扫描结果 → 刮削核对 → 查看媒体库”。根据阻塞原因给一个主要下一步；空目录、权限不足、离线磁盘、重复 Root 和无法识别的命名分别反馈。目录类型仍由用户确认，不静默猜成 Mixed。
- 验收：新用户不用输入路径即可走完流程；取消选择不保存；扫描失败不重复建 Root；已有未处理扫描时直接继续；无可信元数据时不把工具候选伪装成媒体库内容。
- 依据：S1、S6；复用现有 Root、扫描任务与候选确认服务。

### P0-3：核对队列持久化与真实结果汇总

- 问题：目前的第 i/n 项只是位置，离开或重启后缺少统一入口判断哪些已确认、跳过或失败。
- 方案：在应用数据库持久化普通核对队列与逐项状态，至少区分待核对、暂缓、已确认元数据、失败。旁车输出有独立结果，不能把“已确认元数据”显示成“已写入文件”。提供继续未完成、查看失败、重试所选失败项及结束汇总。
- 验收：重启后可显式继续；跳过可再次选择；已完成项不重复提交；删除资源、改变 Root 或隐私权限后重新校验。中断中的动作先核实后端结果，恢复队列不自动重放写入；旧输出预览重新生成。
- 依据：S5、S6；先定义状态/迁移/IPC，再做界面。维持 32 项上限，容量提升另行测量。

### P0-4：把失败变成可执行的下一步

- 问题：底层能识别失败，不意味着用户能知道该改 Token、等限流还是更换检索词。
- 方案：按实际返回结果提供“配置凭据并返回”“修改搜索”“等待后重试”“重选离线目录”等操作。区分凭据已保存、Provider 已启用和实际请求验证成功；如增加连接检查，仅在用户点击后发起只读请求。网络失败保留当前项和草稿，切换目标后丢弃迟到响应。
- 验收：401/403 不当作普通瞬态错误持续重试；429 尊重底层冷却，不虚构倒计时；超时可取消；无候选不报网络错误；重试不重复确认/写盘；诊断不包含 Token。后端尚未返回的信息先补契约，前端不推断。
- 依据：S6 的暂缓与恢复思路，结合本项目现有网络契约；不是声称社区项目使用相同错误分类。

### P1-1：匹配依据与原文件并排比较

- 方案：在已有匹配原因基础上，把本地文件名、解析标题/年份、候选标题/年份、来源和外部 ID 放在同一核对区域；突出冲突项，提供修改检索词、按外部 ID 重搜和暂缓。优先补用户做判断需要的信息，默认折叠技术细节。
- 验收：同名跨年份电影、重制版、剧集与电影同名、番剧别名和缺年份都有可区分结果；无数据标未知。没有校准依据不显示“99% 正确”；再高匹配也不自动确认。
- 依据：S2、S6；涉及解析/匹配规则变更时补纯逻辑样例，不能只改颜色。

### P1-2：面向修复任务的筛选与保存视图

- 方案：基于已有健康过滤增加可核验的具体缺失字段查询，再提供“缺海报”“资料不足”“待核对”等快捷视图；逐项状态视图依赖 P0-3。保存筛选条件时不保存失效游标；“缺 NFO”与“未刮削”是不同状态。
- 验收：筛选作用于完整库；总数与列表用相同查询语义；分页不漏项、不重项；移除 Root 或关闭成人入口后，保存视图不越权。缺少数据支撑的视图不显示假的计数。
- 依据：S3、S4；先明确 SQL 查询语义和索引，不继续增加前端内存过滤。

### P1-3：记住合法偏好，减少逐项重复设置

- 方案：允许保存普通媒体类型对应的 Provider、元数据语言、图片语言和字段预设。应用语言与元数据语言可以分别选择；只展示适配器实际支持的选项。每个目标重新计算“仅补空缺”，不能沿用上一项的字段勾选结果。
- 验收：不支持的语言明确回退；图片语言与元数据语言分别标明实际值；手改/锁定字段继续保护；0 和 false 不视为空；Token 仍手动保存且不进入偏好文件。普通、成人、音乐偏好分域。
- 依据：S2 的图片来源语言差异、S5 的字段策略、S6 的别名语言偏好；完整语言矩阵属于后续契约工作。

### P1-4：输出预览让用户看得懂后果

- 方案：在现有计划上展示精确目标路径和创建、保留、冲突、跳过结果；清楚区分更新应用元数据与生成磁盘旁车。已有组织/恢复功能继续使用独立入口；失败后提供对应计划详情，不承诺统一“一键撤销”。
- 验收：已有 NFO/海报不被覆盖；预览后源文件变化必须重新预览；输出与元数据确认分别记录；使用小型临时真实文件核验 NFO 可读性、图片格式和保留未知字段，记录外部媒体中心验证版本及未测项。
- 依据：S3；具体写入和恢复规则以 [media-output.md](media-output.md) 为准，不复制其他工具的自动重命名行为。

### P1-5：给键盘和窄屏完整操作路径

- 方案：给选择、进入核对、上一项/下一项设置明确的焦点顺序和可发现快捷操作。弹窗关闭后恢复触发点焦点；进入新队列项后通知标题与位置。窄屏优先显示匹配判断信息，将次要元数据折叠。
- 验收：仅键盘可完成选择到确认；输入框内快捷键不误触发；Enter 不跨过确认步骤；图标按钮有可访问名称。1648×928、390×844、减少动态效果，以及加载/空/错误/缺图状态均保留真实截图。
- 依据：S2；遵守 [design.md](../design.md) 与仓库 shadcn，不能用页面原生控件临时拼装。

### P2：完成主线后再评估

| 方向 | 价值与前置条件 | 最小验收 |
| --- | --- | --- |
| 多目录导入和拖放目录 | 原生选择已可用后，减少多 Root 设置成本；需单独评估原生权限和事件边界 | 逐目录确认类型、重复识别、取消与部分失败；拖放不自动保存或扫描 |
| 剧集/番剧命名诊断 | 在已有文件名解析与来源详情上展示季集冲突、绝对集数和多 Part 分组依据 | 使用真实命名模式的合成样本；不把绝对集数强行改成假季号；不自动改文件名 |
| 重复与版本比较 | 借鉴 S6 的重复决策，为已有重复风险提示补上文件、版本、年份差异 | 默认保留；同名不是删除依据；用户决定保留关联或进入独立组织预览 |
| 更大队列与只读候选预取 | 通过持久化状态、取消和限流验证后，再评估超过 32 项及少量预取 | 测量内存、请求量、取消延迟；遵守 Provider 限流；不预先确认、写盘或取得成人内容 |

## 4. 推荐交付顺序与开发边界

1. **第一批：首次成功路径。** P0-1、P0-2、P0-4；先复用现有入口与后端错误，补必要契约。通过新用户全流程和失败返回验收后提交。
2. **第二批：可恢复核对。** P0-3，随后接入依赖队列状态的 P1-2；先实现并测试状态持久化和幂等，再展示完成数量。
3. **第三批：准确性与效率。** P1-1、P1-3、P1-4、P1-5；按独立能力交付，不以一次大改替代逐项验证。
4. **第四批：测量后扩展。** 根据实际使用反馈选择 P2，不先增加新 Provider、后台全自动刮削或播放功能。

实施时沿用共享框架与 shadcn、首页与媒体浏览、工具与设置的职责边界；共享文件必须由单人负责。路由保持薄层，feature 页面组织业务组件，hook 管理状态与异步生命周期，匹配/过滤/预设规则保持纯逻辑。队列持久化涉及 Rust/SQLite 时另明确契约负责人，不能仅在前端存一个“已完成”标记。

所有方案保留 MediaAtlas 品牌、只读媒体库、系统关联应用打开、成人隔离、手动 Token 配置和可配置常显入口。不添加内嵌播放器、捆绑浏览器引擎、虚构进度或尚不可执行的按钮。扫描与选择不等于写盘授权；网络搜索、元数据确认、输出预览和执行保持各自的实际状态。

## 5. 验证与文档维护

- 本次仅调研和整理文档，检查引用和差异；不以既往 250 项前端测试等成绩证明待实施建议已经通过。
- 每次实施运行适用的前端、Rust 或 IPC 检查；队列重点验证重启、幂等、部分失败、取消竞争和资源失效，目录重点验证取消与重复保存。
- Windows/macOS/Linux 原生目录弹窗、离线盘/网络盘、系统密钥服务和系统关联打开需要真实平台证据。浏览器 Mock IPC 截图只能证明对应界面流程，不替代原生与真实 Provider 验收。
- 记录任务完成率、从选目录到首次可信入库的步骤数、失败后需要重做的步骤、错误匹配样例与取消耗时；先取基线再定目标，不编造提升百分比。
- 现有文档有历史描述需要随实施同步：README 的“输入本地目录”未反映当前原生选择主入口；[Provider 访问说明](provider-access.md) 的启动环境 Token 回退描述与当前已移除的自动绑定行为需要对齐；[扫描工作流](library-workflow.md) 早期“新增 Root 不自动扫描”应结合显式“保存并扫描”按钮解释，保存本身仍不等于自动扫描。
- 新能力必须附真实截图、运行平台与源码版本；待验证内容持续标明。纯文档更新不需要移动版本 tag。
