# Phase 5 contract — frozen before implementation

Adult workflows use independent `AdultQuery`, `AdultCandidate`, `AdultDetail`, `AdultSearchRequest`, `AdultSearchPreview`, `AdultMatchedCandidate`, `AdultMergeRequest` and `AdultMergePreview` domain contracts in `adult_scraper.rs`. Ordinary Movie/TV/Anime DTOs, matching and authorization remain unchanged. Catalog normalization is a pure adult domain function, preserving raw/namespace/aliases/primary number and an explicit CD/Part; issuer or namespace differences require review. Provider people retain provider-scoped IDs and aliases and are never merged by display name.

`AdultQuery { catalog_number: String, namespace: String, studio: Option<String>, language: String }`; `AdultCandidate { provider_id, remote_id, catalog_number: CatalogNumber, title, studio: Option<String>, source_url, language }`; `AdultPerson { provider_id, remote_id, name, aliases }`; `AdultDetail { identity: AdultCandidate, label: Option<String>, series: Option<String>, release_date: Option<String>, runtime_minutes: Option<u32>, performers: Vec<AdultPerson>, directors: Vec<AdultPerson>, artwork: Vec<ArtworkCandidate> }`. Detail must recheck candidate catalog identity and studio, rejecting mismatched work/issuer. Matching remains catalog/namespace/part/studio-specific, with review reasons and no Movie title/year score.

`AdultSearchRequest { query: AdultQuery, providers: Vec<String> }`; search preview `{ schema_version,run_id,candidates: Vec<AdultMatchedCandidate>,failures: Vec<ProviderSearchFailure> }`; matched candidate `{candidate,reasons,needs_review,duplicate_of}`. `AdultMergeRequest {run_id,candidate_index,media_item_id,selected_fields: Vec<String>,selected_artwork: Vec<usize>}`. Merge preview reuses `FieldDiff` as a provenance transport only and contains `{schema_version,preview_id,media_item_id,fields,artwork,confirmed}`. Confirmation returns existing `MergeResult`. Metadata source storage remains an independent adult table.

`AdultScraperService::new(repo,providers,hub,engine,cache)` with `with_auth_service(auth)`; methods `initialize`, `search`, `search_preview(run_id)`, `detail(run_id,index)`, `preview(request)`, `confirm(preview_id)`, `media_detail(media_id)` and `artwork_preview(run_id,index,artwork_index)` return typed results. History and jobs never appear in ordinary task/network/search views. Dedicated adult commands require a process-local unlock grant and enforce it in the backend on every call. Adult UI exposure preferences are durable; unlock expires on process exit and explicit lock, with no password claims. UI grants are access/privacy controls within the local app, not an OS security boundary.

Access assessment before adapters: DMM/FANZA official affiliate ItemList API, api.dmm.com; requires approved API ID + affiliate ID, metadata/image reuse subject to affiliate terms and applicable rights. Two fields are stored as one validated keyring JSON secret behind a revision-specific opaque ref using method `affiliate`; settings never return its contents. Query authentication uses P3 secret query injection for BOTH fields and keeps them out of URLs/logs/snapshots. Images only allow official HTTPS hosts (`pics.dmm.co.jp`, `pics.dmm.com`). No login/paywall/CAPTCHA bypass. Secondary source is public Wikidata SPARQL catalog-number (P528) metadata with statement qualifiers/issuer preservation; query.wikidata.org, public no credential, CC0 structured data and conservative 1 request/s. This source has limited coverage and is a supplement, never an assertion of complete adult catalog or licensed images. Both disabled by default, actual requests use P3 NetworkEngine; fixtures are synthetic. Live terms/robots/network/account authorization are pending until observed; no multi-site live success claim.

Shared MediaOutputService gains a typed adult-only authorization/channel constructor. Ordinary channel continues rejecting all adult items. Plans persist their channel and execution rechecks it, current root isolation and permission. Adult artwork cache is separate. NFO/selected images use existing capability-confined, no-follow, no-clobber Preserve-only output; source videos are never moved or altered. Batch is bounded backend-held media IDs and immutable previews, explicit confirmation, cancellation and persisted per-item results; ordinary task/output views must exclude it. Cancellation/lock rejects unstarted writes and never replays a plan automatically. Tests operate only on temporary synthetic media and neutral synthetic image bytes.

IPC commands use `{input: ...}` and schema version 1: adult settings/status/unlock/lock; adult search/detail/preview/confirm/media_detail/artwork_preview; adult output_preview/output_execute/output_discard; adult batch_preview/batch_execute/batch_cancel. Search/merge fields match the Rust contracts above. UI is zh-CN/en-US and never directly contacts providers or displays remote image URLs. Default entry hidden, covers hidden, recent visits disabled. Ordinary stats/wall/search/task/inspector and caches exclude adult records even while adult workspace is unlocked.
