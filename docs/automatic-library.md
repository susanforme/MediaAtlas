# 自动媒体库与首屏加载

本次调整按用户最新要求，将默认路径改为添加目录后自动处理，并把成人内容作为统一前端中的资源类型。它替代早期“扫描候选必须手动确认入库”“有可信元数据才允许在媒体库显示”的产品规则；真实文件写入与后台隐私权限不随之放宽。

## 默认使用流程

1. 添加媒体目录，使用系统文件夹选择器并选择内容类型。
2. 目录保存后启动后台更新，进入该目录的媒体列表；启用后的成人类型使用同一个表单和操作。
3. 后台扫描并建立应用索引，本地可用媒体先显示；随后获取来源资料和应用缓存图片。
4. 唯一可靠匹配自动更新元数据。匹配歧义、来源未配置、网络失败或文件变化显示为可处理状态，用户按需更正或重试。

“媒体库”是本地资源的浏览、搜索和系统应用打开入口；应用索引是实现细节，不再要求用户执行独立的“入库”步骤。资料尚未补全不影响普通本地媒体显示；只有远程资料、没有本地文件的记录仍不冒充可打开的媒体。

流程参考 [Emby 媒体库设置](https://emby.media/support/articles/Library-Setup.html)中的类型与目录配置，以及[初始设置](https://emby.media/support/articles/Installation.html)中扫描期间仍可使用应用的方式。[Emby 元数据管理](https://emby.media/support/articles/Metadata-manager.html)提供缺失资料刷新与人工更正思路。本项目没有复制其播放、服务端转码或账户体系。

## 后台更新契约

- 新增 `library_sync` IPC，调用 `ScanService::start_automatic`。界面不靠定时发起 `scan_confirm` 模拟自动化；任务在后端运行，离开页面不影响处理。
- 任务保存 `mode`、`phase`、已识别/待处理/失败计数，阶段为扫描、索引、元数据、完成。逐项结果持久化到应用数据库，页面只展示实际进展，不把目录文件数当成最终影片数。
- 自动索引复用原有文件身份、路径范围、Root 配置快照与幂等验证。一个文件失效不应丢弃同页其他有效文件；新增目录失败后重试不重复创建目录。
- 搜索仅使用当前启用且满足凭据条件的来源。电影/剧集使用 TMDB、动画使用 AniList；Token 不从运行环境自动读取。未配置时媒体仍可浏览，并提示配置来源后更新。
- 自动识别采用唯一精确标题/别名或精确外部 ID，并检查已知年份与身份冲突；多个可匹配候选或模糊匹配留待处理，不直接选搜索结果第一项。
- 已有本地元数据和已确认来源资料优先保留；人工修改/锁定字段不覆盖。自动下载仅写应用缓存，NFO/海报旁车、音频标签、移动/重命名仍走独立预览和明确执行。
- 取消覆盖扫描和正在进行的网络操作；最终提交再次校验任务、目录配置及媒体关联。退出后保留可查询结果，中断任务不在启动时自动重放写入。
- 普通目录的 opt-in Watcher 在宿主配置自动刮削服务时复用自动流程；它仍只监控用户已经明确启用的目录。
- 成人类型使用独立的目录/文件授权、番号与命名空间精确匹配和成人 Provider；`start_automatic_adult` 持有可撤销会话授权，禁用分类会取消扫描及网络请求并阻止迟到发布。未配置来源时仍显示授权范围内的本地媒体。成人自动流程不进入普通缓存，不自动监控目录。

原有手动扫描接口保留用于兼容。旧扫描待确认任务在界面提供“更新媒体库”迁移入口，不再要求逐个确认发现的文件。音乐保留自己的本地标签读取和来源流程，成人按番号识别，不能套用普通电影来源。

## 成人资源的统一前端

- 设置只保留启用开关，启用后在电影、剧集、动画等共享媒体类型选项中提供成人类型；不单独设置成人侧栏中心或“普通/成人”分区选择器。
- 浏览、详情和工具使用统一路由与布局：`/library?kind=adult_video`、`/media/<id>?kind=adult_video`、`/tools?kind=adult_video`；旧地址保留兼容跳转。
- 应用根据已保存的启用设置自动建立后台会话授权，没有额外解锁页或锁定按钮；选择分类时调用独立成人 API。普通“全部”列表、普通搜索、首页和普通刮削队列不因此包含成人内容。
- 开关关闭时立即隐藏数据、取消查询并清理缓存。旧“隐藏封面/最近访问”前端设置退役：已启用类型使用正常封面显示，并关闭独立最近记录；设置写入串行化，避免迟到的启用请求覆盖关闭操作。

## Tauri 首屏：先处理加载路径，再考虑框架

[Tauri 官方前端文档](https://v2.tauri.app/start/frontend/)支持 SPA、SSG 和静态页面，并推荐 Vite。当前 React/Vite SPA 与 Tauri 的静态资源宿主方式相符，本轮不引入 SSG：用户的本地媒体数据只有运行后才能经 IPC 获取，构建时生成页面不能缩短数据库或目录访问耗时。

查到并处理的路径：

- 前端原先提前加载媒体工具、来源管理等模块，首页还经由包含目录/设置的页面集合间接加载。改为按路由加载非首屏页面，避免首页依赖无关页面集合。
- HTML 提供暗色的静态品牌启动画面，主界面加载时给出实际可见内容；它只是启动壳，不伪装成媒体数据，也不额外引入服务端或浏览器引擎。
- Tauri `.setup` 原先等待旧 NFO 文件检查和目录监听恢复。两者移到后台，慢媒体盘不再是该阶段结束的前置条件。数据库打开、迁移、恢复及必要服务初始化仍保留先后约束。
- 日志记录固定启动阶段名、耗时和成功状态，便于实机区分服务初始化、旧资料检查和监听恢复，不记录用户路径、Token 或原始错误。

生产前端测量与原生启动是两种证据。Chromium 的资源字节、首次绘制和页面可见时间不能替代 Windows WebView2、macOS WKWebView 或 Linux WebKit 的实机冷启动；当前界面证据见 [screenshots/README.md](../screenshots/README.md)；首屏性能须基于当前生产构建另行测量，不延用已移除的旧启动截图或历史数值。

## 验收重点

- 添加目录到本地媒体可见全程没有手动确认入库；单独缺少元数据不隐藏本地文件。
- 重复更新不重复建媒体；无来源、无结果、歧义、部分失败、取消、目录变更和重启中断都能查询真实状态。
- 可靠自动匹配和手改保护使用临时数据库/合成媒体验证；源文件内容与旁车集合不变。实时 Provider 与系统密钥服务需另记实机结果。
- 成人类型只有启用时出现；切换类型不混用 API、参数或缓存，关闭后不残留内容。
- 1648×928、窄屏、键盘、减少动态效果，以及加载/空/错误/缺图状态保存真实截图并标明 Fixture。
- 首屏按生产构建验证资源加载和可见时间；不将压缩包体积下降直接写成原生启动提升百分比。
