# Phase 8 contract

P8 delivers usable maintenance controls, truthful compatibility and licensing evidence, and a beta release pipeline with verified native packages. A configured workflow or pushed tag alone is not release completion. Tests use only generated temporary data; source media is never changed by maintenance.

## Ownership

- Maintenance backend owns new `infrastructure/src/maintenance.rs` and `maintenance/*`. The phase lead owns its module export, IPC, lifetime/startup integration and frontend controls. SQLite remains SQLx. `DatabaseLease` acquires an operating-system exclusive file lock for the complete app lifetime, before opening any database pool. A queued restore executes only at the next startup under that lease, before services or pools exist.
- License worker owns `THIRD_PARTY_NOTICES.md`, `LICENSE-STATUS.md`, `docs/dependency-licenses.json`, `docs/third-party-licenses/*` and `scripts/licenses/*`. Inventory must be tied to actual lockfiles and copy required original license/copyright/NOTICE texts, including bundled native code. The project's source license remains unspecified; no new source rights are granted. FFmpeg/ffprobe are development fixture tools and are not shipped.
- Release worker owns `.github/workflows/release.yml`, `.github/tauri.release.conf.json`, `scripts/release/*`, and `docs/release-matrix.md`. Four required native platforms build concurrently; Windows/Linux ARM are explicitly not built in this beta so unavailable optional runners cannot delay release. Actual payload architecture, version, notices and checksums are checked before release publication. Linux beta provides deb only; AppImage is explicitly not built until its bundled-native-library corresponding-source gate is complete. Required failure blocks publication; optional failure is reported honestly.
- Phase lead owns frontend/API/IPC integration, app version alignment, upgrade and acceptance documents, complete checks and final commit/tag preparation. The parent only pushes commits/tags. No branch/worktree or tag rewriting.

## Database and maintenance invariants

Backups use SQLite-consistent snapshots (`VACUUM INTO` or a backup API), never copying a live WAL database. Immutable manifests carry format, app and migration/schema versions, length and SHA-256. User-requested full backup creation and restoration require backend Preview then explicit Confirm. Exact historical migration line-ending normalization first preserves a private internal recovery snapshot, which is never listed or exposed as an ordinary export. A full backup may contain adult metadata, paths, local history and opaque credential references; the UI explicitly warns, and any private database content requires a current revocable adult grant. Source media is never traversed or copied, but full database backups may contain historical music-tag recovery bytes already embedded in operation records. Secret values from the OS keyring or session never enter backup or diagnostic exports. Restoring elsewhere does not imply credentials are available.

Restore validates integrity, manifest/checksum and supported schema before queuing, then validates again at startup. Future/invalid/corrupt databases are rejected. The current database receives a safe consistent recovery snapshot before replacement; no active pool is renamed or overwritten. No-clobber staging/quarantine, an interruption journal and external-change checks preserve original/replacement bytes on faults. Startup never replays media moves, output or tag writes. Existing source files and quarantine/backups remain untouched. Cancellation and size/work limits bound maintenance jobs; diagnostics serialize only allowlisted versions, fixed error codes and aggregate counts, never raw logs, URLs, paths, queries, tokens, titles or adult payloads. Cache work is limited to an approved application cache directory and requires Preview/Confirm.

IPC retains `{input: ...}` / `{schema_version:1,data:T}` and stable safe errors. Frontend accepts opaque backup/preview/job IDs; raw executable commands and arbitrary database destinations are unavailable.

## Compatibility and release evidence

The application reuses system WebViews: Windows uses installed WebView2 or the official installer bootstrapper (no fixed-version engine bundle), macOS uses WKWebView, and Linux deb depends on system WebKitGTK/GTK. No bundled Chromium or player. Manual updates retain app-data; migrations are forward-only and transactional. This beta has no enabled automatic updater, fabricated signing key or notarization claim. Unsigned status and OS/runtime requirements are explicit. Downgrade means restoring a compatible prior backup using a compatible app; an older app must reject future migration versions.

Use existing pagination, 10,000-file cancellation, provider isolation and image dedupe regression evidence where valid; add critical maintenance failure tests. Required checks are `pnpm check`, `cargo fmt --all -- --check`, full-workspace locked Clippy with warnings denied and full-workspace locked tests, plus release preflight/verifiers. Native CI compilation and package inspection do not establish interactive installation, playback, native association or keyring acceptance. Final acceptance records distinguish executed evidence from pending platform checks. Only published, downloadable and verified packages count as release availability.
