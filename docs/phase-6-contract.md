# Phase 6 Music contract

Music stays independent from video scraping. The persisted graph is Artist → ReleaseGroup → Release → Medium → Track → Recording, using existing domain entities, ordered credits, aliases and typed identifiers. Provider import selects a concrete Release MBID; group/title equality never authorizes merging editions. Existing user-modified/locked metadata remains authoritative. All ordinary Music entrypoints reject adult/isolation/adult-root associations, including reclassified media.

## Integrated IPC and edition evidence

`music_import` accepts only a selected `mbid`; trusted backend fetches and validates the graph. The frontend cannot submit its own provider attribution. `music_release` is the read-only candidate detail. `music_local_files` returns current ordinary scanned audio candidates; `music_link_track` binds one local file to one active concrete edition track (multiple formats per Track are allowed). Rebinding to another Track is a conflict rather than silent reassignment.

Music dates retain provider text precision (`YYYY`, `YYYY-MM`, `YYYY-MM-DD`) in addition to P1 full-date types. Release disambiguation is retained. `assess_music_release` checks concrete Release MBID, artist/album, exact provided date precision, country, edition text, ordered per-disc tracklists and disc count. It always requires explicit edition selection; scores never authorize metadata merging or disk writes.

`music_cover_preview` accepts a stored release ID, matching Release MBID and index; backend fetches CAA metadata, validates canonical cover identity, downloads through shared bounded image processing and returns a PNG data thumbnail with source and rights notice. It never passes remote image URLs to an HTML image element.

All commands use `{schema_version:1,data:T}` and `{input:{snake_case:...}}`, including empty `{input:{}}`. Tag history is persisted and enables explicit restore preview; filesystem restoration remains a separate confirmation.
