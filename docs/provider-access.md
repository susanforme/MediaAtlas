# P4 built-in provider access and live acceptance

The adapters below perform real HTTP/GraphQL requests through the P3 NetworkEngine. They are not fixture adapters. All ship disabled. Synthetic local HTTP tests inject endpoints only under `cfg(test)`; those passing tests do not establish live connectivity or account authorization. No live provider was accepted during this implementation.

Alternative anime providers were assessed before choosing AniList: AniDB HTTP API requires registered client parameters and restrictive rate/reuse policies, so no unregistered implementation is shipped. Neither deferred provider is claimed supported.

## Credential and transport composition

Settings explicitly supports TMDB `bearer` (v4 Read Access Token) and `api_key` (v3 query key). AniList and Wikipedia advertise only public `none`. Secret input is inbound-only: status returns method/storage/configured/status, never the secret. Settings do not imply live credential validation and saving auth does not enable a provider.

`ProviderAuthService` stores only method, storage and an opaque revision reference in SQLite. Native `system` credential storage is the default and fails explicitly when the OS service is unavailable. Users may explicitly choose `session_only`, which expires at process exit and never silently falls back to disk. Every saved revision gets a fresh UUID reference; immutable jobs snapshot that reference. Changing credentials atomically commits the new reference and a secret-free retirement outbox entry. Cleanup runs only after that commit. A failed SQLite write keeps the previous credential usable. A key-service deletion failure returns a successful saved configuration with `cleanup_pending`, keeps the old opaque reference tracked, and retries through subsequent status/save/clear calls; it never reports a completed save as failed. Clear atomically removes the active configuration and records the same cleanup intent, so a failed clear SQL transaction retains the previous usable credential. Logically retired references cannot authenticate even while physical key deletion is pending. An old job can retain its captured method or fail with credentials unavailable; it never adopts a new method or token.

`VideoProviderHub::with_auth_service` resolves those immutable references. Bearer values enter only the Authorization header. API-key values use a dedicated `RequestSpec::secret_query` and enter only the actual original-origin request, never stored URLs/source links/request records. Cross-origin redirects for query-auth requests are rejected, including a hostile Location that reflects the secret. TLS, target validation and proxy protections remain unchanged.

Trusted startup may use an existing `TMDB_PRIVATE_TOKEN` environment binding, with `TMDB_READ_ACCESS_TOKEN` as a compatibility name. It creates a new session-only UUID revision only when no auth configuration exists; it never overwrites a user's saved choice, rebinds a historical reference, persists proxy placeholders to the keyring, or restores an expired user session silently. A saved session that expired requires explicit resaving or clearing before a runtime fallback can be adopted. The standalone legacy hub constructor retains fixed `tmdb.access_token` lookup for existing backend fixture composition; the Settings-backed production composition uses revision references.

Presence of a runtime binding does not establish trusted proxy DNS/SSRF enforcement or live authorization. P3's default proxy fail-closed policy remains in force. Do not put secrets in repository files, logs, chat or command arguments. The provider hub never reads environment variables, accepts endpoint configuration over IPC, overrides proxies or disables TLS/SSRF checks.

## Bounds and partial data

Search is one provider result page (TMDB page 1 / AniList page 1 with 25 entries); it is a candidate shortlist, not an exhaustive remote catalog. Candidate responses over 50 entries, more than 40 TMDB seasons, more than 1500 TV episodes, more than 500 artwork entries per category, or more than 200 AniList synonyms fail explicitly with `response_too_large`. No series is silently returned as complete after truncation. NetworkEngine independently caps compressed response bytes, request concurrency, retries, request durations and image requests. Artwork is not downloaded by the provider adapter: only official allowlisted HTTPS host URLs are returned for later bounded image validation/cache. No DVD, absolute or anime episode mapping is invented from TMDB aired numbering.

## Validation status

Local mocked HTTP tests cover real adapter request/response paths, auth-header injection and redacted inspector records, Movie title/year variants and IMDb lookup, Movie details/artwork/external IDs, TV series→season→episode identities, AniList GraphQL→aliases/IDs/languages/artwork, Wikipedia HTML→supplemental metadata/license, missing credentials, identity/path injection and resource caps. This evidence does not imply current live site availability, robots clearance for a specific deployed crawler, Windows native startup, or account approval.
