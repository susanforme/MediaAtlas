## 2026-11-05 — identity correction and community providers

Manual search accepts a complete IMDb title URL (including mobile URLs, subpages and tracking parameters), `tt…`, `imdb:tt…`, or an IMDb namespace plus the numeric identifier. The same normalization applies to the main title input and the advanced external-ID input before validation and persistence. Supported TMDB, Douban, Bangumi, AniList, MAL and TVmaze addresses also become typed IDs; input URLs are never fetched. Unknown hosts, mismatched namespaces, credentials and unsafe paths are rejected. A specified identity never falls back to an unrelated title search, and fetched details must match the requested IDs.

The source selection follows real community use: [tinyMediaManager's scraper list](https://www.tinymediamanager.org/docs/scrapers) includes OMDb; [MetaShark](https://github.com/cxfksword/jellyfin-plugin-metashark) and [OpenDouban](https://github.com/caryyu/jellyfin-plugin-opendouban) demonstrate Douban metadata workflows. Independent TVDB/AniDB adapters remain deferred pending their access requirements; IMDb URL lookup is provided by TMDB/OMDb, not a bundled IMDb browser scraper.

## Credential and transport composition

Settings explicitly supports TMDB `bearer` (v4 Read Access Token) and `api_key` (v3 query key). AniList, TVmaze and Wikipedia advertise only public `none`. Secret input is inbound-only: status returns method/storage/configured/status, never the secret. Settings do not imply live credential validation and saving auth does not enable a provider.

`ProviderAuthService` stores only method, storage and an opaque revision reference in SQLite. Native `system` credential storage is the default and fails explicitly when the OS service is unavailable. Users may explicitly choose `session_only`, which expires at process exit and never silently falls back to disk. Every saved revision gets a fresh UUID reference; immutable jobs snapshot that reference. Changing credentials atomically commits the new reference and a secret-free retirement outbox entry. Cleanup runs only after that commit. A failed SQLite write keeps the previous credential usable. A key-service deletion failure returns a successful saved configuration with `cleanup_pending`, keeps the old opaque reference tracked, and retries through subsequent status/save/clear calls; it never reports a completed save as failed. Clear atomically removes the active configuration and records the same cleanup intent, so a failed clear SQL transaction retains the previous usable credential. Logically retired references cannot authenticate even while physical key deletion is pending. An old job can retain its captured method or fail with credentials unavailable; it never adopts a new method or token.

`VideoProviderHub::with_auth_service` resolves those immutable references. Bearer values enter only the Authorization header. API-key values use a dedicated `RequestSpec::secret_query` and enter only the actual original-origin request, never stored URLs/source links/request records. Cross-origin redirects for query-auth requests are rejected, including a hostile Location that reflects the secret. TLS, target validation and proxy protections remain unchanged.

Desktop startup does not read or automatically bind environment credentials. Users explicitly save credentials in Settings; an expired session requires explicit resaving. The internal session-binding helper remains available for isolated backend composition/tests, but is not called by production desktop startup. The standalone legacy hub constructor retains fixed `tmdb.access_token` lookup for existing backend fixture composition; the Settings-backed production composition uses revision references.

Presence of a runtime binding does not establish trusted proxy DNS/SSRF enforcement or live authorization. P3's default proxy fail-closed policy remains in force. Do not put secrets in repository files, logs, chat or command arguments. The provider hub never reads environment variables, accepts endpoint configuration over IPC, overrides proxies or disables TLS/SSRF checks.

## Bounds and partial data

Search is one provider result page (TMDB page 1 / AniList page 1 with 25 entries); it is a candidate shortlist, not an exhaustive remote catalog. Candidate responses over 50 entries, more than 40 TMDB seasons, more than 1500 TV episodes, more than 500 artwork entries per category, or more than 200 AniList synonyms fail explicitly with `response_too_large`. No series is silently returned as complete after truncation. NetworkEngine independently caps compressed response bytes, request concurrency, retries, request durations and image requests. Artwork is not downloaded by the provider adapter: only official allowlisted HTTPS host URLs are returned for later bounded image validation/cache. No DVD, absolute or anime episode mapping is invented from TMDB aired numbering.

## Phase 6 public music providers

MusicBrainz public API metadata and Cover Art Archive require no configured credential in this implementation; user-secret Settings continue to serve providers that need authentication. MusicBrainz sends the real project User-Agent `MediaAtlas/0.1.0 (https://github.com/susanforme/MediaAtlas)` and the shared transport enforces at least one second between site requests even when generic limits are set to zero. Retry-After is respected; MusicBrainz redirects fail closed. Discogs remains optional/unconfigured.

Required live hosts are `musicbrainz.org`, `coverartarchive.org`, `archive.org`, plus numbered `ia<digits>.archive.org` / `ia<digits>.us.archive.org` CAA storage hosts. A saved environment wildcard is network configuration only: code accepts only CAA release/image-bound paths and validated same-image archive redirects, with HTTPS/public-IP/TLS/size checks on every hop. No live request was validated in this environment. Core MusicBrainz metadata is CC0; supplementary data can be CC BY-SA. CAA images retain individual copyright, source and rights notices, with no blanket reuse license. Selected covers persist in backend cache/SQLite for Library reads without new provider acquisition.

## Directory-scoped automatic source ordering

Each root stores an ordered `metadata_providers` list. An explicit empty list keeps local indexing and NFO reading active without fetching remote metadata; an omitted list preserves the previous root selection or the established default for older roots. The selection never changes a different root or enables a global provider. Shared provider credentials remain manually saved and globally disabled providers remain disabled. Ordinary automatic enrichment tries eligible providers in the selected order, falls back on missing configuration, failed acquisition or zero matches, and stops at an ambiguous identity for manual review. The first reliable source owns the automatic result; conflicting fields are not silently mixed across sources. Native NFO metadata and protected fields remain preferred. Adult provider eligibility also requires its existing issuer namespace, so changing priority never equates DMM and Wikidata catalog IDs.

The source list participates in immutable scan snapshots and final transaction validation. Directory edits during active scans are rejected, and stale source selections cannot publish metadata after their directory configuration changes. Migration 0021 adds only the nullable root setting; existing roots and files retain their identity and paths.
