# Phase 7 contract

Phase 7 implements file organization, opt-in watching, health review and read-only local consumption. Filesystem changes always require an immutable backend Preview followed by an explicit Execute. Preserve is the default. Tests operate only on generated temporary media.

## Ownership and integration

- Organizer owns `infrastructure/src/organization*`, migration `0015_organization.sql`, and organizer tests. `OrganizationService` is constructed with repository, with a separate revocable adult constructor. It exports serializable backend DTOs and preview/execute/cancel/rollback-preview/rollback-execute/recovery methods. Immutable snapshots bind source, destination, all attachments, Root/scope, bytes and identity. Move, Copy, Hardlink and Preserve use capabilities/no-follow and no-clobber publication; journal each filesystem stage before continuing. Rollback never overwrites an externally changed file. Restart marks interrupted without replay.
- Watcher/health owns `infrastructure/src/watcher*`, `health*`, migration `0016_watcher.sql`, and tests; may edit scanner traversal only to exclude app private backup/quarantine files while preserving configured exclusion semantics. `WatcherService` owns actual notify handles and shared lifecycle; events invoke only the existing read-only ScanService pipeline, never confirm/import/network/output. Persist opt-in configuration, restore active handles explicitly at startup, debounce/coalesce with bounded queue and overflow rescan. `HealthService` reads missing assets, duplicate identities and inaccessible local files; fixes link to existing explicit tools and previews.
- Library readiness/native opener owns `browse.rs`, `library_ready.rs`, `video_open.rs`, `music_library.rs`, `music_open.rs`, two Music artwork tool-read adaptations, scan importer readiness hooks, migration `0017_library_ready.sql`, backend tests. Ready requires explicit confirmed provenance or valid imported local metadata plus a current authorized local playable file. Bare filename imports and remote-only graphs remain tool candidates. Separate tools list/detail API uses existing DTO shapes and pagination. Ordinary/adult native open accept file_id only, require current lane/root/file role/authority and ready provenance, and dispatch through maintained open crate. Native success means requested only.
- Frontend owns frontend library/adult/tools/routes/API/i18n/tests. Consumption pages perform only reads and user-selected native open. Metadata editing, scraping, export, organizing and repair controls live in tools. Preserve privacy entry_visible versus unlocked and old-epoch denial. UI APIs coordinate DTOs with backend implementers; frontend never accepts native command/program/args/URL.
- Phase lead owns Tauri commands/state/bootstrap, module exports, dependencies, docs and integration checks. Agents do not commit. Migration numbers and files above are reserved.

Library/tools read endpoints preserve existing globally paginated DTO shapes; readiness filtering occurs in SQL before pagination. Music domain remains separate, existing Music library native-open contract remains intact. Adult plans permanently revoke on lock, and fresh unlock requires fresh preview. Adult organization targets only current enabled adult roots; ordinary organization rejects any adult association.

Windows uses maintained safe no-replace publication and fixed ancestor leases, with explicit process-session preview expiry. Actual Windows/macOS/native association behavior remains pending unless run. SQLx remains the database adapter; dependency choices and platform limitations are recorded in acceptance.


## Integrated API and limits

IPC uses `{input: ...}` and `{schema_version:1,data:T}`. `library_tools_media`/`adult_tools_media` retain BrowseQuery/MediaPage; tools detail takes only `media_id`. `library_open`/`adult_open` and `music_open_file` accept only `file_id` and return `requested`. Music remote editions use `music_tools_library`/`music_tools_album`; consumption commands require linked local ready editions.

`organization_preview` accepts `media_item_id,target_root_id,template,strategy`; every subsequent organization plan/log/execute/cancel/discard/rollback command accepts `id`. Adult names use `adult_organization_*` with their own live grant. Plans add `kind: organize|rollback`; files include role/source/target/bytes/conflict/same_path. History gives state/completed/already_applied/error_code, with immutable plan and journal reads separately available. Current privacy is rechecked for historical reads too. Cancellation returns only after execution acknowledges stopping; it does not represent a still-running operation as stopped.

Organization previews have a 60-second filesystem work budget, 4096-file cap and 16384-entry directory cap; execution uses streaming hash/copy with 64 KiB cancellation/grant checks on bounded blocking workers. At most two filesystem previews run concurrently, one organization execution runs process-wide, and 32 ten-minute process-local capability sessions live at once. Ordinary organization is video-specific and rejects Music-root targets; Music tag organization stays independent. Private original and rollback quarantines are retained, never automatically cleaned.

Watcher status fields are `root_id,opted_in,active,pending_rescan,last_task_id,error_code`; configure takes `root_id,enabled`. Restore queues one read-only catch-up per current generation to cover offline event gaps. Health accepts `cursor,limit` and returns paginated media/title/issues/repair_route with no implicit repair. The desktop approves only its ordinary artwork cache for asset checks; arbitrary stored paths are not read.
