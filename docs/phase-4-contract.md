# Video scraping and authentication contract

This contract defines typed scraping, manual confirmation and authentication. The automatic library service may accept only a unique reliable match under the current [automatic workflow](automatic-library.md); ambiguous results still require review. It extends the NetworkEngine and SQLite boundaries. No browser scraping, implicit proxy bypass, source-video move/delete, or credential in wire types.

## Type and workflow contract

`VideoQuery` is a tagged Movie/TV/Anime enum; each type has its own search input, results and metadata. `VideoCandidate` and `VideoMetadata` tagged unions carry provider identities, IDs, source URL and locale. Movie/TV match IDs first then title/year; Anime uses its independent alias/year rules. Conflicting years/IDs always require explicit candidate selection. DVD/absolute/anime order is never inferred from TMDB aired order.

`ScraperService`: search(request) → SearchPreview (persistent run, candidates/reasons); detail(run_id, candidate_index) → tagged detail; preview(run_id, candidate_index, media_item_id, selected_fields, selected_artwork) → MergePreview; confirm(preview_id) → persisted merge; output uses a separate explicit confirmation. Backend keeps all untrusted provider results and confirmation snapshots; UI cannot supply arbitrary metadata, paths or URLs for execution. Source/locale/protected flags appear in field diffs. Protected local/user fields cannot be overwritten by provider confirmation; locale comparison normalizes tags. Empty remote values never erase values.

IPC commands: `scraper_search {input: request}`, `scraper_detail {input: {run_id,candidate_index}}`, `scraper_preview {input: request}`, `scraper_confirm {input: {preview_id}}`, `scraper_output_preview {input: {media_id}}`, `scraper_output_execute {input: {preview_id}}`, `scraper_history {input: {}}`, `scraper_search_preview {input: {run_id}}`, `scraper_media_detail {input: {media_id}}`, `scraper_artwork_preview {input: {run_id,candidate_index,artwork_index}}`, `scraper_output_discard {input: {preview_id}}`. Responses use schema_version 1. Search request: `{query: {kind: movie|tv|anime, title, year, external_ids: [{namespace,value}], language}, providers: string[]}`. Provider IDs: `tmdb`, `anilist`, `wikipedia.html`. UI explicitly marks fixtures and unverified live availability. All UI copy uses zh-CN/en-US.

Shared output is Preserve-only P4: plan persists immutable payload/hash and expected destination fingerprint; NFO/selected poster writes only, explicit execute; no original-media operation. Unknown XML fields survive safe NFO rewriting; existing local manual fields are protected. DTD/entities rejected. Destination containment, symlink rejection, before-image verification, preserved originals, operation records, retry/recovery and content-hash idempotency are mandatory. Image engine has compressed-byte/dimension/decoded-pixel limits, MIME/signature validation, SHA-256 cache dedupe and thumbnails. All downloads use P3 transport.

## Provider access assessment before implementation

- TMDB: official v3 API, Movie/TV search, external-ID find, details/images/external IDs and aired seasons/episodes. Requires personal API access and attribution; https://www.themoviedb.org/terms-of-use and https://developer.themoviedb.org/docs/faq. Default disabled; no assumption of commercial license. Revision-specific opaque credential references resolved through system key store; explicitly selected session-only storage is available through Settings; no production environment binding is loaded. Hosts api.themoviedb.org / image.tmdb.org. Live acceptance pending authorized binding and network.
- AniList chosen first: public read-only GraphQL https://graphql.anilist.co, title/alias/year/format/season/episodes/IDs; rate limits and https://docs.anilist.co/terms-of-use apply, no OAuth needed for public metadata. Images use s4.anilist.co, subject to returned URL safety checks. No scraping gated content. Live acceptance pending.
- AniDB: HTTP API registration/client parameters, rate limiting and restricted reuse make it a later explicit opt-in; no unregistered requests. Bangumi: public API feasible, requires identifiable User-Agent and licensing review; deferred after the first adapter. TVDB deferred pending subscription/API access conditions.
- Wikipedia HTML example: single explicitly supplied article-title lookup in English Wikipedia, no broad crawler/search discovery, no login/paywall/CAPTCHA bypass. Parse ordinary article heading + introductory paragraph / description and source links through the P3 HTML engine; metadata is a supplemental candidate requiring manual selection. Terms https://foundation.wikimedia.org/wiki/Policy:Terms_of_Use, robots https://en.wikipedia.org/robots.txt, text CC BY-SA attribution/share-alike requirements, image rights excluded. HTML provider does not export third-party images. Default disabled, identifiable User-Agent, conservative request interval; CAPTCHA/403/429 remain classified failures. Fixture parsing does not establish live access or licensing clearance.

Local tests use explicit mock servers and synthetic data; no fabricated live-provider success. Third-party filesystem candidates assessed: ignore/notify are reserved for P7; retain SQLx rather than adding rusqlite/tantivy. file-id was inspected: public high-resolution Windows APIs reopen paths rather than consume an existing capability handle. P4 instead uses opened-file Unix identity and bounded Windows no-delete leases; it does not claim low-64-bit IDs uniquely identify ReFS files.

## User-specified authentication settings extension

The user explicitly requires editable per-provider authentication in Settings. Secret input is Deserialize-only and never logged, returned, put in snapshots/SQLite, localStorage or source URLs. Provider auth methods initially: TMDB `bearer` (v4 Read Access Token) / `api_key` (v3 query key); AniList/Wikipedia `none` (public read-only). Unimplemented Basic/OAuth/Cookie methods are not advertised. Save credentials and provider enablement are separate actions.

IPC follows the established `{input:...}` wrapper: `provider_auth_status {provider_id}` → AuthStatus `{provider_id,supported_methods,method,storage,configured,status}`; `provider_auth_save {provider_id,method,storage,secret}` → AuthStatus; `provider_auth_clear {provider_id}` → AuthStatus. Method IDs `none|bearer|api_key`, storage `system|session_only`. Save clears secret inputs on success/failure; status never returns secrets. System CredentialStore is the default durable storage, OS failure is explicit; session_only requires explicit user selection, expires at process exit, and never silently falls back to plaintext. Changing method retires old credential/session references; references only appear in immutable job config. Production startup never reads or automatically binds environment credentials. Users manually configure and save credentials; session storage expires at process exit. Authentication never bypasses NetworkEngine proxy/SSRF/TLS policy.

TMDB API-key requests use a dedicated SecretString query parameter added only to the actual request for the original origin; request records/source URLs/snapshots remain free of the secret and cross-origin redirects are rejected for query credentials to prevent reflected secret disclosure. Auth-mode changes must affect actual Mock requests, not only settings DTOs. Authentication settings do not test/claim live site authorization merely because a value is saved.

Authentication retirement failures are recorded as opaque references in a durable cleanup outbox. A successful new configuration with pending old-key cleanup returns configured=true and status=cleanup_pending; it is not reported as a failed save. Status refresh retries cleanup without returning secret material.
