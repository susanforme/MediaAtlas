# 数据维护、升级和失败恢复

在应用“设置 → 诊断与维护”打开备份与维护。浏览器预览没有数据库权限；以下操作使用真实桌面 IPC。维护不移动、删除或改写源媒体，不重放标签、组织或导出计划。

## 完整备份

选择“预览完整数据库备份”，阅读范围后“确认备份数据库”。SQLite `VACUUM INTO` 生成一致快照，包含已提交的 WAL 内容，不复制运行中的 `.sqlite` 文件。每份备份为应用数据目录 `maintenance/backup-<UUID>/`，含 `library.sqlite` 和 `manifest.json`；manifest 记录格式、应用版本、迁移版本、大小与 SHA-256。保留这两个文件及目录名；可完整复制该目录到另一台电脑同一应用的 `maintenance` 目录，再刷新列表。

完整备份包含所有元数据、Root/文件路径、用户字段、历史及隐私数据；不是普通公开导出。存在成人数据时，后端要求当前有效的成人会话授权；设置启用开关由应用自动建立该授权，不增加独立解锁页。关闭分类永久撤销旧预览，重新启用必须重新预览。请把备份放在只有本人可读的位置，不上传公开问题或诊断附件。备份不遍历或复制库中源媒体，OS keyring 或会话秘密不进入备份。完整数据库本身可能包含 P6 标签写入的历史恢复字节，因此备份可能间接包含历史音频文件字节，不能当作无媒体内容的公开材料。仅保存数据库中原有不透明凭据引用；在另一系统恢复通常需要重新保存认证，`configured` 状态以实际凭据可用性为准。应用不提供备份加密或 OS 权限隔离承诺。

## 恢复与故障处理

从列表选择“预览恢复”，阅读替换/安全快照/重新认证提醒，然后“确认下次启动恢复”。确认只排定计划；**完全退出应用后重新打开**。尚在运行的 SQLite pool 不会被覆盖。下一次启动先取得数据库操作系统独占实例锁，再在所有 pool、Watcher、任务和服务创建前验证并恢复。第二个应用实例不能同时使用该数据库。

恢复先核对原始 manifest、完整 SHA-256、SQLite 完整性、迁移 checksum/版本和应用版本，拒绝损坏、未知格式及未来版本；迁移在隔离候选库完成。替换前，对当前数据库生成一致的 `before-restore.sqlite` 安全快照；原始数据库及候选库保留在专有 `restore-<UUID>` 目录。无覆盖发布、恢复 journal 和前后复核使竞态/异常保留字节，绝不盲目覆盖外部新增文件。启动中断后只保留已验证的原库或已完成的候选，不自动重试原恢复或任何媒体写入。

遇到 `maintenance_recovery_required`，保留 `library.sqlite*`、整个 `maintenance/restore-*`、pending plan 与 journal。不要为“重试”删除唯一原库或安全快照。应用会停止启动以避免在不明状态继续写库；先复制这些恢复材料到私有安全位置，再由熟悉 SQLite 的维护者检查 manifest/hash 和候选完整性。当前 beta 没有自动丢弃冲突字节的“一键修复”。

## 手动更新与数据保留

当前 main 的迁移集合上限为 **19**，包含 [持久化人工核对账本](review-queue.md)。完整备份会保留队列及检查点记录；恢复或重启后只读取并重新核验，不自动执行遗留确认。已失效/过期的资源和预览需要新核对。此状态属于后续 main，不代表既有 beta.3 包已经包含 schema 19。

本 beta 未启用自动 updater；未配置发行签名、Apple notarization 或更新签名密钥，不制造值，也不绕过校验。只从[项目 Releases](https://github.com/susanforme/MediaAtlas/releases)获取匹配原生平台的包，对照 `SHA256SUMS`。更新前在应用中创建备份并完全退出；随后使用安装包更新或替换便携应用。应用标识 `com.mediaatlas.desktop` 与数据目录稳定，程序包不包含媒体或用户数据库。

数据库迁移向前且逐迁移事务执行；SQLx 拒绝未知的未来迁移和已执行迁移 checksum 不一致。项目及发布 checkout 固定 LF，原始第三方许可材料保留原字节。历史开发库仅对官方同一 SQL 的精确 LF/CRLF SHA384 提供兼容：必须完整成功版本前缀，且表、索引、触发器及 SQLx 历史表的实际 schema 与官方前缀完全一致，才允许将已知 CRLF 记录规范为 LF。不会在任意 checksumMismatch 后重写 expected；额外自建索引/触发器、修改 schema、未知或未来 checksum 均失败保全，不承诺任意旧库都能升级。

仅在上述已验证兼容情况下，程序先在数据库旁 `.mediaatlas-migration-backups/<UUID>/before-upgrade.sqlite` 保存 SQLite 一致内部安全快照，验证实际 no-follow 对象、完整性、原历史和 checksum，再于事务内重新检查并仅更新精确匹配的记录。原库用户数据不被清空，原始备份文件保持不变；恢复只在已核对 manifest SHA 的隔离候选副本上规范化。这些内部恢复材料可能含隐私元数据和历史标签字节，不进入普通导出/备份列表，也不自动删除。Unix 在文件 flush 后同步三个目录层；Windows 执行文件 flush，不冒称已完成实机断电测试。

迁移失败会停止启动，不回填成功或静默清空数据。备份恢复先迁移隔离候选，避免损坏当前库。旧程序无法承诺读取新格式：需要降级时使用兼容旧应用版本的旧备份并保留新库副本，不把新数据库直接交旧程序。升级失败后可重新安装原版本并保留数据；若 schema 已前进，应使用升级前备份。安装、升级、卸载和 OS 默认数据保留的实际交互验收仍按平台报告状态记录；用户选择卸载删除数据或手工删除数据目录无法被应用保证保留。

应用复用系统 WebView，不捆绑 Chromium 或固定浏览器引擎。Windows 便携包要求已有 WebView2 Runtime；安装器可按官方 bootstrapper 下载安装。macOS 使用系统 WKWebView，Linux deb 使用外部系统 WebKitGTK/GTK 依赖。

各系统默认数据目录由 Tauri 解析（Windows `%APPDATA%/com.mediaatlas.desktop`、macOS `~/Library/Application Support/com.mediaatlas.desktop`、Linux `$XDG_DATA_HOME/com.mediaatlas.desktop` 或 `~/.local/share/com.mediaatlas.desktop`）。以页面显示的实际目录为准，不根据路径猜测或自动覆盖。

## 安全诊断与缓存

“导出安全诊断”写入上述应用维护目录，只使用固定版本/schema/platform、允许的固定错误码和聚合统计。不会打包原始日志、URL、本地路径、查询、token、任务 payload、标题或隐私名称。导出位置只在本地 UI 显示，不进入诊断文件。单次后台工作有体积/数量/时间预算，可请求取消；页面保持运行状态直至后端确认结束。

图片缓存重置先预览文件数/大小，再确认，只处理预先批准的普通 artwork-cache，拒绝 symlink、预览后变化和未知路径。文件无覆盖移入维护隔离区并复核实际对象，保留原始字节，因此本操作不释放磁盘空间。保留成人图片、数据库、备份及媒体；缩略图可重新生成。当前不提供自动删除恢复隔离区或旧备份，避免误删仅存原始字节。
